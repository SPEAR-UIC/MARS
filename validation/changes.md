# Changes Made During the Backfill Divergence Investigation

Companion to `backfill_divergence_investigation.md`. This file is the
authoritative record of what was — and wasn't — changed in each codebase.

## C++ (`cqsimcpp`, `src/`)

**No source changes.**

`results/cqsimpy-test1` and `results/cqsimpt-test2` were stale (built from
an older binary). They were regenerated by rebuilding the existing,
unmodified source (`cmake --build build --target cqsimcpp`) and rerunning
`experiments/cqsimpy-test1.json` / `experiments/cqsimpy-test2.json`. That
alone resolved divergence #1 (job 49 / job 24, theta21cln).

Temporary `fprintf`-based tracing was added to
`src/core/backfill.h::schedule_with_backfill_reservation` twice during the
investigation, to confirm the exact admission conditions (`shadow_time`,
`free_at_shadow`, `cond1`/`cond2`) computed at specific scheduling cycles.
Both times the instrumentation was fully removed afterward (`git checkout --
src/core/backfill.h`, then rebuilt), and `git diff`/`git status` were used
to confirm a clean tree before moving on.

## Python (`cqsim-python/src/`)

**No source changes.**

Two edits were made and tested, then reverted:

1. `cqsim-python/src/CqSim/Node_struc.py::pre_reset` — removed the
   `or i == 0` clause. **This was wrong.** It let the predictive
   reservation timeline treat jobs ending at exactly "now" as already
   released even when their own `End` events hadn't been processed yet by
   the simulator's event loop, causing over-admission beyond real free
   capacity.
2. `cqsim-python/src/Extend/SWF/Node_struc_SWF.py::pre_reset` — the same
   change, to the subclass that is actually used at runtime for SWF-driven
   experiments (`Node_struc_SWF` overrides `pre_reset`; the fix above to
   the base class never took effect during testing because of this
   override — this was a source of confusion mid-investigation before the
   override was found).
   `Node_struc_SWF.node_allocate`'s job_list insertion already has a
   `break` after insert (unlike the base class's version, which is missing
   one — a separate, latent, never-triggered issue in `Node_struc.py` that
   was also touched and reverted along the way; it was never confirmed to
   cause any observed symptom).

Applying both changes together removed the *symptom* (job 75's start time
matched, correlation on the theta21cln comparison hit 1.0000 on the ~57
jobs that completed) but exposed a **worse**, previously-latent bug:
`Cqsim_sim.start()` (`cqsim-python/src/CqSim/Cqsim_sim.py`) never checks
`node_allocate()`'s return value, so an over-admitted job is marked
"running" and gets an `End` event scheduled regardless of whether real
allocation succeeded. When that `End` event later fires,
`Node_struc_SWF.node_release()` can't find the job in `job_list` and raises
`IndexError: pop index out of range`. Both `theta21cln` and `polaris24cln`
runs, which previously completed all 1000 requested jobs, crashed after 57
and 28 jobs respectively.

Given the real root cause is architectural (Python's event loop makes one
backfill decision per individual event rather than batching same-timestamp
events — see `backfill_divergence_investigation.md`), this `pre_reset`
change was reverted rather than shipped as a partial/unsafe fix:

```
git checkout -- cqsim-python/src/CqSim/Node_struc.py \
                 cqsim-python/src/Extend/SWF/Node_struc_SWF.py \
                 cqsim-python/src/CqSim/Cqsim_sim.py \
                 cqsim-python/src/CqSim/Backfill.py
```

All temporary debug instrumentation (env-var-gated `print`/`fprintf` calls
added to `Backfill.py`, `Node_struc.py`, `Node_struc_SWF.py`, and
`Cqsim_sim.py` at various points) was removed the same way. `git status`
was checked after each revert to confirm no stray diffs remained.

`cqsim-python/data/Results/theta21_events.csv` and
`cqsim-python/data/Results/polaris24_events.csv` were regenerated one final
time from the unmodified source (1000/1000 jobs completed each) so they
reflect the current, unpatched behavior of `cqsim-python` — the same
behavior that was present before this investigation started.

## What would need to change to actually fix divergence #2

Not implemented, per the decision to stop at documentation. Would require
batching same-`sim_time` `End`/`Submit` events in
`cqsim-python/src/CqSim/Cqsim_sim.py`'s `scan_event()`/`event_job()` before
running a single `start_scan()`/`backfill()` pass, so a burst of
simultaneous job completions is evaluated as one combined capacity change —
matching the C++ `SchedulingCycle` model in
`src/adapters/simulation/driver.cpp` / `simulator.cpp`.
